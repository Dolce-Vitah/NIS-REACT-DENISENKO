# Отчет по проекту Smart Data Dashboard Builder

## Суть приложения

Smart Data Dashboard Builder — это веб-приложение для импорта табличных данных (`CSV`/`JSON`), построения интерактивных 2D/3D-дашбордов и их последующего анализа в режиме Discover. Пользователь может добавлять виджеты, настраивать поля и стили каждого виджета, применять фильтры, сохранять состояние рабочего пространства, создавать закладки и экспортировать результат в несколько форматов. 

## Использованные технологии

`React 19` использовался как основа интерфейса и компонентной модели. Он хорошо подходит для сложных интерактивных панелей с большим количеством состояний и условного рендера. По сравнению с `Vue` React дает больше свободы в архитектурных паттернах и экосистеме, но требует более дисциплинированной организации кода при росте проекта.

`Material UI (MUI)` использовался для базовых UI-компонентов (меню, табы, диалоги, формы), что ускорило разработку и обеспечило визуальную консистентность. По сравнению с `Ant Design` MUI лучше интегрируется с кастомным theming и React-паттернами, но часто требует более тщательной настройки `sx`/стилей для нешаблонного вида.

`Sass` применялся для глобальных и инфраструктурных стилей (например, поведение resize/drag, общие переменные и служебные классы). По сравнению с “чистым CSS” Sass удобнее для структурирования больших стилей и повторного использования миксинов/переменных. Альтернатива в виде CSS-in-JS могла бы уменьшить число отдельных style-файлов, но осложнила бы часть глобальных правил.

`Zustand` использовался как слой клиентского состояния для дашборда, фильтров, UI-настроек, Discover и фоновых jobs, включая persist и undo/redo сценарии. В сравнении с `Redux Toolkit` Zustand проще по API и быстрее внедряется, особенно для feature-driven структуры. При этом Redux дает более формализованные паттерны для очень крупных команд.

`Three.js` применялся для 3D-виджетов (`3D Bar`, `3D Scatter`, `3D Surface`) и интерактивных визуализаций с drilldown-поведением. По сравнению с готовыми chart-библиотеками (например, `ECharts` 3D режимами) Three.js дает максимальный контроль над сценой и поведением, но требует больше инженерной работы для поддержки и синхронизации с темой/палитрой.

`react-router-dom` использовался для маршрутизации и разведения сценариев по страницам (`/dashboard`, `/discover`). В сравнении с ручным условным рендером по mode-state маршрутизация дает более предсказуемую навигацию, удобные deep links и лучшее соответствие ожиданиям пользователя.

`@monaco-editor/react` применялся как расширяемый редактор запросов для Discover-сценариев. В сравнении с обычным `TextField` он дает значительно лучший UX: подсветка, удобное редактирование, пространство для дальнейших language-features. Это тяжелее по весу бандла, но ценность для сценария “аналитического запроса” заметно выше.

`@tanstack/react-query` использовался для асинхронных операций вокруг collaboration/publish flow и управления статусами загрузки. По сравнению с ручными `useEffect + useState` или хранением сетевых статусов в обычном сторе React Query дает устойчивый контракт для async-состояний, retries и кэширования, что снижает связность UI и API-слоя.

`Vitest + Testing Library` применялись для unit-тестов и проверки пользовательских сценариев на уровне компонентов/функций. По сравнению с `Jest` Vitest быстрее стартует в Vite-проектах и проще в настройке. Testing Library в отличие от shallow-подходов фокусируется на поведении и пользовательском взаимодействии, что лучше отражает реальные регрессии.

`ESLint + Stylelint + Prettier` использовались как quality-gate для детерминированной проверки кода и стилей. В сравнении с точечным ручным ревью это дает воспроизводимое качество и защищает от деградации стандартов при частых изменениях. Компромисс — необходимость периодически рефакторить код под ограничения complexity/правила, но это же улучшает архитектуру в долгую.

## Заключение и рефлексия

Проект получился как практический “мини-аналитический” продукт и одновременно как инженерный стенд для демонстрации технологий: от управления состоянием и маршрутизации до 3D-визуализации и quality-процессов. Наиболее полезным оказался связанный эффект от сочетания `TypeScript + Zustand + quality gates`: рефакторинг крупных компонентов (например, правой панели и навигации) можно выполнять безопасно и предсказуемо. Наиболее интересной по впечатлениям стала связка `Three.js` с UI-слоем MUI: она дала богатую визуальность, но потребовала внимательной синхронизации стилей, тем и интерактивного поведения. В целом выбранный стек показал хороший баланс между скоростью разработки, гибкостью архитектуры и устойчивостью к расширению функциональности.
