# E-Commerce Admin Panel

## Инструкция по запуску

### Установка и запуск

1. **Клонируйте репозиторий и перейдите в папку проекта:**
   ```bash
   cd e-commerce-admin
   ```

2. **Установите зависимости:**
   ```bash
   npm install
   ```

3. **Запустите сервер для разработки:**
   ```bash
   npm run dev
   ```
   Приложение будет доступно по адресу: `http://localhost:5173`

4. **Сборка для продакшена:**
   ```bash
   npm run build
   ```

5. **Проверка линтером:**
   ```bash
   npm run lint
   ```

## 🛠 Технологический стек
- **Core:** React 19, TypeScript
- **State Management:** Redux Toolkit, Redux Persist
- **Data Fetching:** RTK Query (API: DummyJSON)
- **Routing:** React Router v7
- **Styling:** Tailwind CSS
- **Animations:** Framer Motion
- **Forms & Validation:** React Hook Form, Zod
- **i18n:** react-i18next
- **Notifications:** Sonner
- **Architecture:** Feature-Sliced Design (FSD)

## Реализованные улучшения и их обоснование

Проект был значительно расширен по сравнению с базовым ТЗ:

### 1. Premium SaaS UI/UX Дизайн
*   **Что сделано:** Внедрена пастельная цветовая палитра (розовые и сиреневые тона для светлой темы, глубокие сливовые для тёмной), эффекты Glassmorphism (размытие фона у сайдбара и хедера), кастомный полупрозрачный скроллбар, замена стандартных иконок на согласованный SVG-пак.
*   **Обоснование:** Базовый "черно-белый" дизайн выглядит скучно. Премиальный UI повышает лояльность пользователей, делает интерфейс современным, визуально приятным и снижает когнитивную нагрузку за счет мягких контрастов.

### 2. Продвинутые анимации (Framer Motion)
*   **Что сделано:** Плавные fade-in/fade-out переходы между страницами (AnimatePresence), stagger-анимация (поочередное появление) строк в таблице продуктов, плавное изменение ширины сайдбара без скачков верстки, анимация вращения иконок при смене темы.
*   **Обоснование:** Анимации создают ощущение "бесшовности" и отзывчивости приложения. Они помогают пользователю понять контекст происходящего (например, что данные загрузились и появились на экране) и делают взаимодействие с приложением "живым".

### 3. Оптимистичные обновления (Optimistic UI)
*   **Что сделано:** Реализована кнопка удаления продукта. При клике продукт мгновенно исчезает из таблицы (и из кэша RTK Query), не дожидаясь ответа от сервера. Если сервер возвращает ошибку, UI незаметно откатывается назад.
*   **Обоснование:** Это сложный паттерн управления кэшем, который является стандартом для современных веб-приложений. Он создает иллюзию нулевой задержки (zero-latency), что критически важно для UX в админ-панелях.

### 4. Строгая валидация и производительность форм (React Hook Form + Zod)
*   **Что сделано:** Форма авторизации переписана с использования обычных `useState` на связку `react-hook-form` и `zod`.
*   **Обоснование:** Использование неконтролируемых компонентов (RHF) избавляет от лишних ререндеров при каждом нажатии клавиши. Zod обеспечивает строгую статическую типизацию (TypeScript) от схемы валидации до отправки данных на сервер, исключая ошибки человеческого фактора.

### 5. Отказоустойчивость (Error Boundaries)
*   **Что сделано:** Создан компонент `GlobalErrorBoundary`, оборачивающий всё приложение.
*   **Обоснование:** В случае непредвиденной ошибки рендеринга (например, из-за битых данных с сервера), приложение не упадет с "белым экраном смерти". Пользователь увидит красивый fallback-интерфейс с описанием ошибки и кнопкой перезагрузки, что является обязательным требованием для Enterprise-приложений.

### 6. Система уведомлений (Sonner) и Пустые состояния (Empty States)
*   **Что сделано:** Интегрирована библиотека `sonner` для красивых всплывающих toast-уведомлений. Создан переиспользуемый компонент `EmptyState` для отображения заглушек (например, когда поиск не дал результатов).
*   **Обоснование:** Качественный UX требует постоянной обратной связи. Пользователь должен четко понимать результат своих действий (успешный вход, ошибка удаления) и не должен видеть просто пустой экран, если данных нет.

### 7. Семантика и Доступность (a11y)
*   **Что сделано:** Использование семантических HTML-тегов (`main`, `article`, `nav`, `aside`), добавление `aria`-атрибутов, поддержка `prefers-reduced-motion` (отключение анимаций для пользователей, у которых это задано в настройках ОС).
*   **Обоснование:** Делает приложение доступным для скринридеров, улучшает структуру кода и показывает профессиональный подход к веб-разработке.
